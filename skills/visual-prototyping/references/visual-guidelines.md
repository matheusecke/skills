# Visual guidance

Choose fidelity proportional to the question; do not require a wireframe-to-mockup sequence. For an existing product, reproduce the relevant established visual language using isolated HTML and selectively copied permitted static resources. Do not import application modules requiring a runtime, build or authentication. Explain simplifications and deliberate differences.

Default to one proposal for iterative refinement. For comparison, prefer two or three meaningfully different structures, hierarchies or interactions, without treating that as a hard limit. Use equivalent data, scenarios and simulated widths when fairness requires it. Allow side-by-side and individual viewing, expansion and restoration; on narrow screens retain simulated widths and allow scrolling. Flow and comparison may coexist. Simulate only the screens and states needed to evaluate the decision, including a repeatable reset where needed.
