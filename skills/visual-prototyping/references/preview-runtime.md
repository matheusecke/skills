# Preview runtime

Requires Bash 3.2+, Node.js 22+ and a modern browser with EventSource. Prepare the catalog and contents first. Start with `bash <skill>/scripts/start-server.sh --session-dir <session>`; use `--foreground` in a persistent agent job when detached processes do not survive. Stop with `bash <skill>/scripts/stop-server.sh <session>`. Start emits a JSON connection record after readiness; reuse does not open another browser. Verify `GET <url>health` returns the published instance ID after launch and before claiming a preview is running. If the agent cannot maintain a process, give the exact foreground command to run in a user terminal.

Runtime state lives under the system temporary directory in `visual-prototyping-<sha256(home)>/<sha256(real-session-path)>/`, outside the project, with restricted access. A custom TMPDIR must be outside the project and its Git worktree. Do not redirect connection output into a project file. Stopping preserves content, credential and last port. If private state is lost the new URL cannot reconnect the old tab; if the prior port is occupied, navigate to the new URL. Never kill by port or PID alone.

The server binds loopback only. Automatic browser opening is best-effort; provide the URL even when unavailable. In SSH, WSL or containers explain that access is on the server host and local port forwarding may be needed; do not expose a public bind, create tunnels or change firewall settings automatically. Git Bash is best-effort; PowerShell/CMD without Bash are unsupported. Linux, macOS, WSL and agent job persistence require their own environment validation.

The preview keeps mode, selected proposal and simulated width during updates. An iframe reload can reset its internal form, scroll or flow state. Selection is not communicated to the agent. Invalid or partially written catalogs show a recoverable error while retaining the last valid catalog. Polling scans only the small content tree; writes that artificially preserve size and mtime are outside the detection guarantee.
